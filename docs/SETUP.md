## Команды

Из корня репозитория:

```sh
make setup
make explore
make validate
```

Для навыков не требуется активировать venv вручную: Makefile использует `.venv/bin/python`.
Если навыки установлены в другом месте, задай `make CODEX_SKILLS=/полный/путь/к/skills validate`.

## Подключение к Элементу

Аккаунт и среда разработки уже доступны Лёше. Текущие облачные идентификаторы и URL не содержатся в исходном репозитории.

1. Открой существующий проект ReliabilityLab в своей среде 1CmyCloud и сопоставь его с `alexkey/ReliabilityLab/Проект.yaml`. Не создавай второе приложение автоматически.
2. Для управляемого развёртывания через `xbsl-deploy` заполни **локально** `.env`: `ELEMENT_BASE_URL`, `ELEMENT_CLIENT_ID`, `ELEMENT_CLIENT_SECRET`; по возможности app/project/space ID и ветку. Это параметры management API, а не HTTP API заказов. Пароли и секреты не отправляй в чат.
3. Для прямых проверок бизнес-API сохрани его фактический HTTPS URL в `RELIABILITYLAB_API_BASE_URL` после публикации сервиса. Сейчас сервиса ещё нет.
4. Перед развёртыванием Codex читает установленный `xbsl-deploy/SKILL.md` и выполняет проверку конкретного приложения и ветки. Эта настройка сама по себе не выполняла deployment/merge.

Docker установлен, daemon был запущен при общей проверке окружения. Контейнеры не создавались. Для текущей части Элемента Docker и RabbitMQ не требуются.
