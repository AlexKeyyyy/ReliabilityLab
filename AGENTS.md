## Инварианты исследования
- Архитектура: Python → RabbitMQ → HTTP adapter → опубликованный HTTPS API Элемента → настоящий сохранённый заказ.
- Первый срез C уже реализован. Продолжай со стратегиями A/B, затем метриками и UI; не выдавай их за готовые.
- `operation_id`, `order_id`, `run_id`, `attempt_id`; время UTC. UNKNOWN — недостоверный исход у наблюдателя, а не доказанная ошибка или отмена бизнес-эффекта.
- HTTP 2xx, сохранение inbox, запись заказа и consumer ACK — разные события. Указывай достигнутую точку фиксации.
- A — изолированный намеренно небезопасный baseline; B не устраняет гонку проверки состояния; C требует устойчивой защиты от повторного эффекта, включая конкурентные запросы.
- Не обещай exactly-once или атомарность без проверки. Сбой после commit должен оставлять фактический заказ доступным для независимого чтения.
- Все метрики и графики — из реальных запусков. Не выдумывай результаты, источники, PASS или научную новизну. UI — с английскими подписями.
- Не добавляй Kafka, Kubernetes, обязательный outbox и тяжёлую инфраструктуру в MVP.
