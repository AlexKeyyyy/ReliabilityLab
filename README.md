# ReliabilityLab

Исследование восстановления распределённых бизнес-операций при неопределённом исходе.
Текущий фокус Лёши — приложение **1С:Предприятие.Элемент 10.0**.

Реализован первый серверный срез: устойчивый приём сообщения, создание настоящего заказа,
идемпотентное восстановление C, история попыток/событий и управляемый откат до commit.
Срез опубликован в [Reliability lab-dev](https://app-802542381.1cmycloud.com/applications/Reliability-lab-dev).

Инструкция, примеры запросов и ограничения: **[docs/FIRST_SLICE.md](docs/FIRST_SLICE.md)**.
A/B, Operations UI и интеграция с RabbitMQ/Python ещё впереди.

## Структура

- `alexkey/ReliabilityLab/` — существующий проект Элемента с сохранённой идентичностью.
- `tests/test_element_api.py` — проверки настоящего опубликованного API на синтетических данных.
- `experiments/acceptance/` — сохранённые свидетельства приёмочных проверок, не исследовательские A/B/C-результаты.
- `AGENTS.md`, `PLAN.md`, `TASKS.md` — инструкции Codex, этапы и текущий статус.
- `docs/ARCHITECTURE.md`, `docs/CONTRACT.md` — проект целевой системы и интеграционного API.
- `docs/TEST_PLAN.md`, `docs/ELEMENT_RESEARCH.md` — приёмочные сценарии и изученные источники.
- `docs/ReliabilityLab_MASTER_PROMPT.md` — копия исходной спецификации.
- `docs/SETUP.md` — инструменты, навыки и подключение к облаку.

## Команды

Требуется Python 3.10+ и установленный набор XBSL skills. Из корня репозитория:

```sh
make setup
make validate
make build VERSION=1.0-5
```

Для live-проверок явно задайте адрес тестового API и токен по инструкции FIRST_SLICE, затем:

```sh
make test-live
```

Проверки создают собственные синтетические записи; Python не заменяет backend Элемента.
Локальная проверка YAML и упаковка .xasm не заменяют облачную компиляцию.

Руководство для Лёши: [как устроен проект и зачем нужны регистры](docs/GUIDE_FOR_LESHA.md).
